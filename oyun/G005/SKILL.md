# A* path finding on a tile grid (python-pathfinding)

Finds shortest paths on a character tile grid with A* from python-pathfinding: per-character costs (0 = blocked), four diagonal modes and up to 64 start/end queries per call. Returns the path cells, step count, total cost and search effort. Used to precompute pedestrian walks, traffic loops and mission reachability once at build time.

MCP server name: `yol-bulma`; tool: `skillpack_g005`.

## When and how to use

Send the tile rows (one string per row, x = column, y = row), a cost per character (0 blocks the cell; default '.'=1, '#'=0) and the start/end cells. Cost is the sum of entered-cell costs (diagonal steps cost sqrt(2) times).

Read manifest.json for the exact schema; do not guess missing data, coerce types or invent values. Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2.

## Place in the game-building flow

Step 2 (rotalar): on the map from G002, compute pedestrian routes on the walk grid and traffic routes on the drive grid, and in step 6 prove every mission target is reachable by car. The paths are embedded in the HTML; the browser never runs A*.

## Scope and failure

Grids up to 128x128, 64 queries and 200000 search runs per call by default; an 8-second search limit is applied. Uniform tile costs only (no one-way roads, no traffic lights). heuristic_weight > 1 is faster but may return non-shortest paths.

## Faithfulness

The upstream modules are vendored unmodified (byte-identical to upstream/) under tool/pathfinding; the Skillpack wrapper adds character-to-cost mapping, bounds and blocked-cell checks, grid.cleanup() between queries, cost reporting (end node g) and a time limit of 8 s instead of the upstream 10 s so the pack watchdog never fires first.
