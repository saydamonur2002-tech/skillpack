# Spherical area of GeoJSON polygons (m², hectares, km²)

Area of a GeoJSON Polygon, MultiPolygon or GeometryCollection on the sphere (holes subtracted), in square metres, hectares and square kilometres, plus the signed area and orientation of a single ring. Answers "how big is this park/neighbourhood/plot?".

## When and how to use

Use only this bounded deterministic operation. Read manifest.json for the exact schema; do not guess missing data, coerce strings/booleans or invent reference values.

Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2. Duplicate keys, nonfinite values, extra properties and oversized input are rejected.

## Scope and failure

Spherical approximation (Chamberlain and Duquette 2007) on a sphere of radius 6378137 m: typically within a few tenths of a percent of ellipsoidal GIS areas, not survey or cadastral quality. Holes are subtracted by absolute value; self-intersecting rings and overlapping MultiPolygon parts are not detected. Input must fit 64 KB, so very detailed boundaries need simplifying first (for example with M021). Orientation sign: positive means clockwise.

## Faithfulness

Line-by-line port of geometry, polygonArea, ringArea, rad and isClosed from index.js at the pinned commit, including the implicit closing of unclosed rings and the same summation order. The ring operation exposes upstream ring() with signed output. Inputs are structure-checked (positions [lon, lat] within range) instead of silently returning undefined for unknown types.
