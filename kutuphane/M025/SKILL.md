# Geohash encode, decode with bounding box, and eight neighbours

Encode latitude/longitude to a base-32 geohash of 1-20 characters, decode a geohash to its cell centre, half-size error and bounding box, or list its eight neighbouring cells (north clockwise to northwest).

## When and how to use

Use only this bounded deterministic operation. Read manifest.json for the exact schema; do not guess missing data, coerce strings/booleans or invent reference values.

Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2. Duplicate keys, nonfinite values, extra properties and oversized input are rejected.

## Scope and failure

WGS84-style latitude/longitude in degrees only by convention; the code is pure bisection on [-90, 90] x [-180, 180] and knows no datum. Lengths 1-20; integer geohash, auto precision from decimal strings, bounding-box coverage search and distance are not exposed. Neighbours near the poles are clamped to the pole latitude (as upstream), so they may repeat the input cell. A point exactly on a cell boundary goes to the lower/western cell because comparisons are strict.

## Faithfulness

Port of encode, decode_bbox, decode, neighbors, ensure_valid_lon and ensure_valid_lat from main.js at the pinned commit: longitude-first bit interleaving, strict greater-than bisection, lower-case decode, neighbour offset of two half-errors and JavaScript % semantics (math.fmod) for longitude wrap. Invalid characters are rejected by schema instead of producing NaN.
