## Faithfulness and changes

Ports geolib v2.0.24 getDistance (Vincenty inverse with toFixed(precision) then Math.round, elevation ignored, NaN for non-convergence turned into an error) and orderByDistance (distance per place, stable ascending sort). With default accuracy 1 and precision 0 distances are whole metres; ties keep dataset order. Filtering by radius, categories, name and the alias table are Skillpack rules. Note: geolib getRhumbLineBearing/getBearing are deliberately not used (their source comment cites GPL-licensed material).

## Reference values

Fixture places are synthetic (CC0). Expected result lists, distances and counts were generated by reference/upstream_harness.js, which loads the same fixture file directly and calls pinned upstream geolib.orderByDistance in Node; the harness re-implements the documented filters independently of the Python port.

Frozen references are in tests/references.json; each case has an `origin` that distinguishes literal upstream fixtures from values generated by executing pinned upstream code. No full-upstream-suite claim is made.
