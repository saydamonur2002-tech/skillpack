# Proleptic Gregorian date to two-part Julian date and MJD

Convert a valid astronomical-numbered proleptic Gregorian year/month/day at midnight to ERFA-style two-part Julian Date, Modified Julian Date and a convenience summed JD. This is a calendar arithmetic primitive, not a timescale conversion.

## When and how to use

Use only this bounded mathematical operation. Read manifest.json for the exact schema; do not guess missing physical data, reinterpret a timescale, coerce strings/booleans or invent reference values. Coefficients, where present, are descending-degree order.

Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2. Duplicate keys, nonfinite values, extra properties and oversized input are rejected.

## Scope and failure

Astronomical year zero exists; negative years are not historical BC labels. Valid range -4799..9999, strict month/day and Gregorian leap-year rules; no adoption-date switch, business days, holidays, timezone, UTC leap seconds or UTC/TT/UT1 conversion. Distinct from the existing financial day-count/business-calendar pack. Keep the two parts for downstream precision rather than assuming the summed JD preserves fine time resolution.

## Faithfulness

Ports eraCal2jd integer arithmetic, including truncation-toward-zero for (month-14)/12. The rest of the dividends are nonnegative in the admitted domain. Unlike ERFA status -3, this adapter rejects an invalid day rather than returning a computed JD alongside an error status. Caps the otherwise broader upper-year range at 9999. Full ERFA BSD license and source SOFA-heritage notice are retained; this is an ERFA-derived adaptation, not an official SOFA distribution.
