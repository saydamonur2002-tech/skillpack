# Encoded polyline algorithm format encode and decode

Encode a list of [latitude, longitude] pairs into the compact encoded-polyline text format (delta, zigzag, 5-bit chunks, precision 0-13; default 5), or decode such text back to coordinates.

## When and how to use

Use only this bounded deterministic operation. Read manifest.json for the exact schema; do not guess missing data, coerce strings/booleans or invent reference values.

Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2. Duplicate keys, nonfinite values, extra properties and oversized input are rejected.

## Scope and failure

Coordinates are [latitude, longitude] numbers (an optional third value is ignored, as upstream); no datum, projection, GeoJSON flipping, range validation of latitude/longitude or route semantics. Values are rounded half away from zero at 10^precision. Scaled values must stay below 2^52 for exactness. Decoding is stricter than upstream: characters outside ASCII 63..126 and truncated values are rejected instead of silently producing coordinates.

## Faithfulness

Port of py2_round, encode, polyline.encode and polyline.decode from src/polyline.js at the pinned commit: Python-2-style rounding, delta from previous rounded point, zigzag sign mapping, 5-bit little-endian chunks with 0x20 continuation and offset 63. JavaScript float shifting (coordinate /= 32, & 0x1f, multiply-by-shift accumulation) is replaced by equivalent exact integer arithmetic within the documented 2^52 bound. fromGeoJSON/toGeoJSON are not exposed.
