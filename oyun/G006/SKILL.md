# NPC steering behaviours: seek, flee, arrive, pursuit (Yuka)

Simulates one non-player character (pedestrian, traffic car or police car) with Yuka's steering behaviours in 2D: seek a point, flee from a threat inside a panic radius, arrive and slow down at a point, or pursue a moving target by predicting where it will be. Integrates force, mass, max force and max speed per step and reports the trajectory and closest distance.

MCP server name: `npc-yonlendirme`; tool: `skillpack_g006`.

## When and how to use

Give the NPC (position, velocity, max_speed, max_force, mass), the behaviour and its target (or the evader for pursuit), the step and number of steps. Yuka defaults are kept: max_speed 1, max_force 100, mass 1, arrive deceleration 3, flee panic_distance 10, pursuit prediction_factor 1. In pursuit the evader moves in a straight line at constant velocity.

Read manifest.json for the exact schema; do not guess missing data, coerce types or invent values. Exactly one JSON object is read from stdin; one JSON result is written to stdout. Success: `{ "ok": true, "result": {...} }`. Failure: `{ "ok": false, "error": {"code": "...", "message": "..."} }`, exit status 2.

## Scope and failure

One agent and one behaviour per call; no behaviour blending, obstacle avoidance, separation or wander (wander is random). Pursuit assumes a straight-moving evader in this simulation. Steering ignores walls: in the game, collisions (G004) push NPCs out of buildings.

## Faithfulness

2D port of Yuka's 3D vector maths on the x-z plane (Yuka y=0). Direction (getDirection) is modelled as the normalised last displacement, which is what Vehicle.update sets through lookAt when speed^2 > 1e-8; before any movement it is the given heading, the velocity direction, or Yuka's forward +z. A single behaviour with weight 1 passes through SteeringManager._accumulate. Smoother is not used (Yuka default null).
